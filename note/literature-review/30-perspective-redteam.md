## 1. 共通問題（各節會引用）

### 1.1 雜訊估計太樂觀
- **0.02% 的來源：** 只有 BE 對 BM 一對（初始化不同、資料順序相同）
  - 只看到一個 |d| = 0.02% 時，σ_d 的 95% 區間是 **0.009%–0.64%**（`ema_tau.py`）
  - 換句話說，一對樣本幾乎無法限制雜訊的上限
- **其他旁證都指向比 0.02% 大：**
  - 150M：同 seed 重跑差 0.2%（一對）；三個 seed 的配對效果 sd 0.15%；baseline 在不同 seed 之間差 0.3%（`optimizer-research/05-results.md`）
  - 1B 一串「打平」的結果散在 +0.04% 到 +0.18%：AR、BA、BX、BZ、BW、BV
  - AI 對 AG（換資料加換順序）差 0.55%
  - AN 的筆記自己寫：「0.32% 可能在 seed 雜訊內」
- **工作假設：** σ_d ≈ 0.05–0.15%
  - 0.3% 的門檻還可以接受
  - BM 筆記說「0.1% 以上可信」，以及 T3a、T4、T5 用的 ±0.05–0.1% 門檻，都不可靠
- **中途的雜訊更大：**
  - BM 對 BE 早期差到 0.8%（第 1146 步），30% 之後仍有 0.4%
  - 所以任何「看中途曲線判斷機制」的檢查都在雜訊裡。例如 K1 的「收益應該集中在後段」、K3 的「5–10% 要領先 0.3%」
  - 例外：同 seed、同初始化的配對，早期的雜訊會比 BE/BM 小，但這個數字沒量過

### 1.2 多重比較與贏家詛咒
- **假贏的機率**（每支候選其實都沒效果，同時測 5 支時，至少一支超過門檻的機率；`ema_tau.py`）：

| σ_d | 門檻 0.1% | 0.2% | 0.3% |
|---|---|---|---|
| 0.05% | 11% | 約 0 | 約 0 |
| 0.10% | 58% | 11% | 0.7% |
| 0.15% | 77% | 38% | 11% |

- **贏家的數字會偏高：** 5 支裡最好的那支，期望上大約高估 1.2σ，也就是 0.06–0.18%
  - 所以 1B 贏 0.2% 的候選，真實效果可能只有一半

### 1.3 對照組是舊數字
- 所有 1B 候選都對 CJ 的 15.324，可是工作目錄 `src/` 有沒 commit 的改動：
  - `muon.py`、`optimizer.py`、`training.py`
  - 新增了 `NORM_LEARNING_RATE`、`polar_express` 分支、EMA 參數的傳遞
- 只要現在的程式跟當時跑 CJ 的程式有任何不同，對比就不乾淨
- **對策：** 同一批**重跑 CJ**（同 seed），一次解決兩件事
  - 量出「同 seed 配對」真正的雜訊
  - 確認程式沒漂移：跟 15.324 差超過 0.05% 就要先查
- 每支 run 的筆記都記下程式狀態（commit 雜湊或 diff 的雜湊）。現在的「code as CL, unchanged」沒辦法驗證

### 1.4 1B → 6B 的縮水
- BY：1B 的 −0.72% 到 3B 只剩 −0.27%（約 1/3）；KD 加 EMA 從 −10.0% 縮到 −8.0%
- 1B 預期 −0.1 到 −0.3% 的候選（K3、K8、K9、K7），到 6B 很可能 <0.1%
  - 在 6B 量不出來，卻帶著全部的程式風險

### 1.5 舊配方量的曲線被拿來做大量外推
- τ 曲線（AI/AK/AL/AN）、衰減比例（AZ/BM/BL）、lr 拋物線（BR/BU/BV），都是在部分舊配方下量的

- 曲率本身都只靠 3 個點，而且點之間的差距跟雜訊同量級

## 2. 各候選

### 2.1 K1：無偏 tail target

**最強的反對理由：文獻量到的缺口，是 α=1 的情況**
- SLS 的 Naive Fix 是「target 全部給老師，剩下的機率給答案」，等於我們的 α=1。我們的 α 是 0.8–0.9，另外有 10–20% 的資料份額
- Busbridge（G.4）：就算是更差的「top-128 重新正規化」，只要混 λ=0.7 的真實答案，就跟完整分布差不到 0.01 nats
- SLS Table 2 的 73%/83% 來自兩位小數的表：K=20 和 K=50 都是 2.76，FullKD 2.74，CE 2.81。差距只有 0.01–0.02 nats，論文沒有報告 seed 的變異
- **我估的上界：** 只算學生最容易學到的「head 和 tail 各占多少」這部分
  - V0 在期望上大約給 tail 3.4%，資料是 7%
  - 這裡假設答案落在 tail 時，m 的平均約 0.65，這是我的假設
  - 理想的 KL 約 0.015 nats（約 1.5% ppl）
  - 跟 Busbridge 類比，實際實現不到一半
  - 所以 1B 比較可能是 **−0.1 到 −0.4%**，T1a 的中位 −0.5% 偏樂觀

**研究員可能高估的地方**
- **6B「可能比 1B 大」的論據引錯表：**
  - T1a 引 SLS Table 8（8B→3B、100B tokens）說差距會變大
  - 但 Table 8 裡的列是一般的 Top-K 12/50（重新正規化），不是 Naive Fix
  - 拿它來支持「我們的 V0 在大規模的缺口會變大」，是張冠李戴
- **兩邊都過度解讀同一個 0.26%：**
  - T1a 把「CI（α 1.0）後段輸 CH」當成偏差的徵兆
  - 可是 Strong Teacher（NeurIPS 2026）用完整 logits，沒有截斷偏差，也看到純蒸餾一般比最佳 α 差（Table 6）。所以 α 有內部最佳值，不需要偏差來解釋
  - 反過來，T6 的「真實偏差只有理想的 1/20」也是從 CI 減 CH 推的，同樣不成立
- **1B 測的 α 跟 6B 不同：**
  - 1B 在 α 0.9 測，6B 用 0.8
  - 偏差跟 α 成正比，理想值 6–8% 對 4–5%
  - 所以 1B 的收益大約是 6B 條件下的 1.3–1.5 倍
- **「無偏」只是近似：**
  - 前提是老師在每個情境下都校準
  - 這個 8B 老師在 top-32 的邊界整體偏不自信（top-32 的總機率 91%，答案落在裡面 93%）
  - V1 會繼承這點，影響小，但不是嚴格無偏
  - 順帶一提：`distill.py` 的 docstring 寫「答案在 top-32 外 9%」，CE 筆記寫的是 7%（裡面 93%），兩者不一致

**靜默失敗與檢查方法**
- **錯位的風險：**
  - label 和 ids 錯一位時，tail 旗標會接近 100%：CE 筆記量過，錯位時答案在 top-32 只有 32.3%
  - 這時 V1 就變成「α 倍老師加上 1.0 倍答案」，看起來在跑，其實是另一個 loss
- **必做的檢查：**
  - 每步記錄 tail 的比例，應該約 7%；也記錄 Σq 的平均，應該約 1 − 0.02α ≈ 0.98
  - 在 CPU 上用 autograd 驗證梯度 (Σq)·softmax − q
  - 把 tail 強制設成 False、data 改回 1−αm 時，結果要跟現在的程式逐位元一致
  - forward 加一個呼叫計數器，第 10 步印出來，確認 hook 仍在 Liger 之後生效（記取 CE 那次 bug 的教訓）

**傷到 6B 的風險：** 低
- 方向有理論支撐，最壞的情況大概是打平
- 要注意的只有一點：tail 位置的權重升到 1+αm，梯度的變異會略微增加
- **K1 進 6B 時，α 維持 0.8：** T1a C3 提議在 K1 之後把 α 提高到 1.0，那個沒測過，不要跟著做

**判決：先做 1B 測試**，前面先跑下面的診斷 D1 把關

**怎樣才算真的贏**
- 對照同一批重跑的 CJ，最終 ≤ −0.25%，而且 70%、90%、100% 三個 eval 點都領先
- 只贏 0.1–0.25% 時不放進 6B，除非 D1 顯示學生確實少給了 tail 一半以上的理想缺口
- 不要拿「收益集中在後段」當機制的證據（§1.1）

**比 K2 的 T* 更直接的把關（D1，幾分鐘的 GPU）：**
- **資料：** 用 1B checkpoint 沒看過的訓練列（第 1B tokens 之後的列；快取裡有老師的 top-32）
- **量 BU 和 CJ 兩個值：**
  - 學生放在老師 top-32 上的總機率
  - 答案落在老師 top-32 的頻率
- **再算一個上界：** 只把 head 和 tail 兩塊的總量重新縮放，NLL 最多能降多少。這就是 K1 能拿回的「總量部分」
- **判讀：**
  - BU 應該接近 0，當對照
  - CJ 的上界 < 0.1% 時，K1 就不值得占一個 slot

### 2.2 K3：α 跟 lr 連動

**最強的反對理由：Peng 的證據其實不支持這個形式**
- **原文的 WSD-α（p.6 正文）：**
  - α 在前 10% 從 0 升到 1，之後固定 1.0，最後 1% 用 cosine 降到 0
  - lr 是同樣的 10% warmup 加 1% 衰減
- **它跟 K3 的差別：**
  - 它跟「1-α+WSD-LR」只差在「α 從 0 暖身」和「最後 1%」
  - 這跟 K3（在 80% 的衰減段線性降到 0.7）完全不同
  - 而且「α 從 0 暖身」是我們自己 D 節排除的做法
- **數字本身也不可靠：**
  - 8.0% 對 5.0% 是 benchmark 平均，單一 seed
  - 主要差在 MMLU 31.8 vs 27.0、C-Eval 33.8 vs 29.1，都在 25% 的亂猜水準附近

**其他反對理由**
- **我們自己的數據在雜訊內：**
  - CI 減 CH 在 20/50/70/90/100% 的差距是 +0.20、0.00、+0.14、+0.21、+0.26%，不單調
  - 早期的 −0.56% 和 −0.33% 落在 §1.1 的早期雜訊帶裡
  - 二次擬合在每個時間點只有 4 支單 seed 的 run，曲率 0.18 nats/α²，非常平
- **α=1 在 stable 段後半就已經不是最好：**
  - CI 在 20% 已經落後 CH（+0.20%），K3 卻讓 α=1 一直撐到 20%
- **前期的領先通常留不到最後：**
  - BX：momentum 0.9 前期領先，衰減段被超越
  - BA：中途 −5%，最終 +0.04%
  - BR/BY：warmup 的收益前大後小
  - T1b 自己估最後只剩 1/4
- **6B 怎麼遷移沒有定義：**
  - 6B 的固定 α 用 0.8，理由是「最佳 α 隨 tokens 下降」
  - K3 的 1B 版本平均 α 約 0.88
  - 6B 該用 1.0→0.7（平均 0.88，跟選 0.8 的理由矛盾），還是 1.0→0.55（從沒測過的低值）？1B 的結果回答不了

**研究員可能高估的地方**
- T1b 把 variance-reduction 理論（線性模型）和 Peng 當成「兩個獨立來源」，但 Peng 講的不是同一件事

**靜默失敗**
- α 是在 `use_mixed_loss(model, alpha)` 時被閉包捕捉的浮點數
- 如果只改 `model.kd_alpha`，forward 還是讀舊的閉包變數，就完全不會生效
- 檢查方法：每步記錄實際傳進 `MixedCrossEntropy` 的 α

**傷到 6B 的風險：** 中。α_end 的對應方式是猜的

**判決：放棄**，6B 維持固定 0.8。只有 1B 的空位 ≥5 支時，才當 K1 的 2×2 配對因子（§4 的 F2）

**真的贏：** ≥0.3%。「前期領先型」的候選最容易被雜訊和贏家詛咒騙

### 2.3 K8：AdamW 組（embedding 和 norm）用較短的衰減

**最強的反對理由**
- **證據是 speedrun，不是 ppl：**
  - 來源是 modded-nanogpt Track 3 #24：124M、約 3000 步
  - 指標是「到達目標 loss 的步數」（3225→3175，步數少 1.6%），不是固定步數下的 ppl
  - 步數少 1.6%，用 ppl ∝ 步數^−0.2 換算，頂多約 0.3%；換到 1.24B 會更小
- **我們的 embedding 是 tied 的：**
  - Track 3 的 embedding 和 lm_head 是分開的（lr 0.7 vs 0.004）
  - 我們的 embedding 同時是輸出層，占 21% 的參數，是 ppl 最敏感的地方
- **研究員互相矛盾：** T4 在「不建議」裡寫「AdamW 組用較短的獨立衰減：理論指向全程衰減，沒有支持的證據」
- **混淆因素：**
  - 較短的衰減代表在峰值待更久，積分 lr 從 0.595 升到約 0.795（×1.34）
  - 等於同時提高 AdamW 組的有效 lr 和有效 wd（τ 是用峰值 lr 定義的）
  - norm 的 lr ×2 / ×4 在 CB/CC 都輸（+0.49%、+0.95%）；embedding 的 lr 往上（AZ）是贏
  - K8 的草圖連 norms 也改成 0.4，兩個方向可能互相抵消；就算贏了，也說不清是哪一個造成的
- **還會牽動 EMA-Nesterov：** β 是用每組自己的 lr 比例算的，K8 會讓 embedding 的前瞻也變長，又多一個混在一起的變數

**靜默失敗**
- 換掉 HF 的排程器時，Trainer 可能仍然建立自己的排程器
- LambdaLR 的 lambda 順序要跟 param_groups 一致
- 檢查方法：在 30%、50%、70% 印出每組的 lr

**判決：放棄**
- 真要試，有一個乾淨的替代：只把 embedding 的 lr 調高，norm 維持（用 `NORM_LEARNING_RATE`），只改設定、不動程式。優先度低

**真的贏：** ≥0.3%

### 2.4 K9：AdamW β1 0.975，或改用 Nesterov AdamW

**最強的反對理由**
- **證據的設定不同：** Secret Sauce 和 Fantastic 都是整個模型用 Adam，我們的 AdamW 只管 embedding 和 norm
- **我們動 momentum 的實驗全部輸或打平：** BD（Muon 0.98）+0.88%、BX（0.9）+0.09%
- **把不同設定的數字直接套過來：**

### 2.8 CM 的中途數據能不能當成「τ 太大」的證據？不能

**比值上升本來就會發生，跟 τ 有沒有錯無關**
- **lr 的效應：**
  - CM 的 lr 比 CL 低（×0.954），每步的 γ = 1/(τS) 也小（×0.667）
  - 所以 stable 段的雜訊底比較低，中途占優勢；衰減段把雜訊收掉時，這個優勢會還回去
  - 「τ 太長」的徵兆也長這樣：AN（τ 較短）在 stable 段落後、衰減後才贏，所以 τ 較長就是中途占優、最後吃虧
  - 兩者的曲線形狀一樣，從形狀分辨不出是哪一個
- **50% 和 85% 不是同一種狀態：**
  - 50% 的 eval 落在 EMA-Nesterov 的視窗內，評的是前瞻點 x + βm
  - 85% 已經在視窗外，評的是原本的權重
  - 跨過視窗邊界比較比值，混了兩種狀態
- **其他的解釋：**
  - KD 的收益隨 tokens 縮小
  - 基準線飽和

**用 CL 自己的最後 15% 來估 CM 的終點**
- CL 在 85% 時約 13.20（= 12.45 / 0.943），結束時 12.635，最後 15% 降了 4.3%
- CM 若降一樣的比例，終點約 **11.92**；若因雜訊底較低而降得少，約 12.0
- **T1b 事先預測的飽和形式是 11.89–11.93**，對上了；剩下可以歸給 τ 的部分最多約 0.5%，也就在外推的誤差範圍內
- 照 T3a 自己的拋物線，Power Lines 對的話，τ 的懲罰在 4.5B 比 3B 只多 0.15–0.6%，跟外推誤差同量級
- 所以 CM 分辨不了「飽和」和「τ 太長」，因為 τ 太長本身也會看起來像飽和

**要分辨的話，有兩個做法**
- 拿同配方、不同長度的一對，看比值在 50% → 85% → 結束的軌跡：BU 對 BY 最乾淨，兩者都沒有 KD 和 EMA，τ 都是 0.39

## 4. 第 F 節問題的回答

### F1：K1 的推導和程式草圖對不對？
- **推導：對**
  - 期望的 target：head = α·p_T + (1−α)·p_data，tail = p_data
  - 前提是老師在每個情境都校準
  - 梯度 (Σq)·softmax − q 正確
- **草圖：對**
  - `(ids != label).all(1, keepdim=True)` 的形狀和 broadcast 都正確
  - bool 乘上浮點數的結果是浮點數
  - 兩行 loss 不用改
  - 被 `keep` 遮掉的位置（BOS、padding）在進函式之前就移除了，不會被誤判成 tail
- **錯的是幅度的論證：**
  - SLS 的缺口是 α=1 量的
  - Table 8 是重新正規化的 top-K，不是 Naive Fix
  - CI 減 CH 不能拿來推偏差，不論往大推（T1a）還是往小推（T6）
- **還要補的：** §2.1 列的四個檢查，加上 D1 診斷

### F2：K1 和 K3 分開測還是疊在一起？
- **分開。** 不要只跑一支 K1 加 K3：
  - 贏了，不知道是誰的功勞
  - 而且 K3 在 6B 的 α 對應方式沒定義，疊在一起的結果沒辦法直接放進 6B
  - 如果一個有幫助、一個有害，疊起來可能只剩小贏，結果把有害的那個也帶進去
- **1B 空位 ≥5 支時：** 做 2×2（CJ 重跑、K1、K3、K1+K3）
  - 每個主效應都由兩組差值平均，雜訊的變異數減半，交互作用也看得到
- **空位不夠時：** 只跑 K1

### F3：K4 的證據夠不夠強，能不能不經 3B 就直接用在 6B？
- **不夠。** 方向（τ 應該變小）有中等的支持，幅度（0.2）沒有：
  - 斜率是從 ≥16 TPP 的 AdamW 外推過來的
  - 1B 的曲線來自舊配方
  - 新配方的 NorMuon、KD、EMA-Nesterov 都把名目最佳 τ 往長的方向推，EMA-Nesterov 已經把有效 τ 壓到約 0.24
  - CM 分辨不了（§2.8）
- **做法：** E1 加 1B 配對（§2.7）
- **E1 跑不了時：** 用 0.25–0.27，不要用 0.2

### F4：10-18 只有一批 1B 加一支 3B，該選哪幾支？
- **送出前先做的（不用訓練，需要你同意送 GPU job）：**
  1. D1 診斷加 K2 的 T*：BU、CJ、CL，用沒看過的訓練列
  2. K11：用 OJ 程式評 CL
  3. 等 CM 的最終值；用 BU/BY 的比值軌跡檢查 CM
- **3B：** E1（CL 加 τ 0.22：Muon wd 0.153，embedding wd 0.0268）。這支沒有替代品
- **1B，依優先序：**
  1. **CJ 重跑**（同 seed）：量雜訊，確認程式沒漂移，也是其他所有支的對照
