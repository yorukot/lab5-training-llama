## 2. 分歧與裁決理由

### K4（τ）：四方都反對 0.2，共識是名目 0.25 左右
- **理論、紅隊、外推的共同發現：** EMA-Nesterov 會把 wd 項一起放大，名目 τ 0.39 的有效值約 0.24，所以 0.2 等於重複下藥
- **我的檢驗（`21-lead-checks.md`）：**
  - 外推派預測「有 EMA 的權重會小 5–15%」，實測反而大了約 23%
  - 原本寫成「放大的大小沒有被證實，但也沒被否定」
- **R1 審稿後的更正：**
  - 權重 RMS 本來就檢驗不了這件事
  - 改做初始權重投影，量到放大 ×1.3–1.5（1B）、×1.2–1.3（3B），比理論穩態值小
  - CL 的有效 τ 約 0.31；6B 名目 0.25 約等於有效 0.2
- **裁決：**
  - 取四方建議的交集，名目 τ 用 0.25
  - 這比 1B 實測的平坦區（0.27–0.55）略短一點，下檔有界
  - 同時也朝「τ 隨 tokens 變小」的方向移動
- **E1（3B，只改 τ）：**
  - 測 0.22。理論派和實務派都選這個值；跟 0.39 的差距夠大，結果才有資訊量
  - 6B 的換算：
    - E1 − CL ≤ −0.2%：6B 用 0.2–0.22
    - ±0.2% 以內：6B 用 0.25–0.27
    - ≥ +0.2%：6B 用 0.33–0.39

### K3（α 排程）：3 比 1 支持測，但只靠我們自己的擬合
- **反對理由（紅隊）：** Peng 的 WSD-α 其實是「α 從 0 暖身、最後 1% 才降」，形式不同；查核也確認了這點
- **支持理由（理論）：** 在 Muon 下仍定性成立
- **跟 K1 的關係：** 如果 K1 成功，α<1 的需要會減少，所以兩者一定要一起看
- **裁決：** 1B 用 2×2 設計測（CJ 重跑、K1、K3、K1+K3）
  - K3 只在「K1+K3 比 K1 再好 ≥0.15%」時才放進 6B

### 小改動 K7、K8、K9：截止前全部放棄
- 1B 預期都在 −0.05% 到 −0.3%，到 6B 很可能剩一半以下（BY 的經驗是 1/3）
- 紅隊估計同時測多支、門檻 0.1–0.2% 時，假贏機率是 11–58%
- 引用查核把 K8、K9 的證據都降級了
- 截止後可以回到 150M 或 1B 上慢慢測

### 雜訊：門檻提高到 0.25–0.3%，同一批重跑 CJ
- **紅隊的觀點：**
  - 0.02% 只來自一對 run，σ 的 95% 區間是 0.009–0.64%
  - 1B 的一串「打平」散在 +0.04% 到 +0.18%，σ 比較可能是 0.05–0.15%
- **處理方式：**
  - 對照組不用舊的 CJ 15.324，同一批重跑 CJ，同時檢查程式有沒有漂移
  - `src/` 有沒 commit 的改動，CJ、CL、CM 跑的都是 working copy

## 4. 營運風險（紅隊與實務，比多數候選更重要）
1. **程式狀態：**
   - CJ、CL、CM 用的是沒 commit 的 working copy，nano4 和本機也沒有 git 同步
   - 6B 送出前，要比對 nano4 和本機 `src/*.py` 的 sha256，並記錄在 note 裡
   - 建議你 commit 一版，標成 CL/CM 的程式
2. **環境變數打錯字會靜默退回舊預設：** 例如 KD_ALPHA 0、EMA 0、批次 64、warmup 5%、衰減 50%
   - 開跑後要核對：Trainer 印的 steps（約 45.8k）和 examples（732,756），以及第 100 步的 lr
3. **中斷續跑從沒測過：** `trainer.train()` 沒有傳 resume 參數
   - 6B 中途失敗時只能從頭跑，所以 A、B 平行或保留備援名額很重要
4. **時間：** 6.84 h、54.7 H200-h；節點慢 5% 時是 7.2 h
   - 在 step 500–1000 比較 tokens/s，慢 10% 以上就換節點重送
5. **資料長度：** 要確認 `max_steps × 16 ≤ 資料列數`，而且 DataLoader 多抓的那一個 batch 也在快取範圍內
6. **事後溫度要預留 tokens：** 6B 的 `MAX_TOKENS` 建議設 5,995,000,000，留 5M 給調 T
